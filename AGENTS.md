# Project reference instructions

Before every Unreal work session, check for John's manual updates before modifying, reloading or regenerating content. Follow `Documentation/Unreal-Reference/Session-Start.md`. Treat the current saved project and any unsaved editor changes as work to preserve; old generation scripts and screenshots are not authoritative over newer edits. John intends to make aesthetic edits himself while leaving mechanics to our collaboration. Limit changes to the requested scope, and resolve any actual overlap before overwriting his work.

Before Unreal implementation or troubleshooting, consult `Documentation/Unreal-Reference/README.md` and the relevant recipe. Reuse tested workflows where applicable. After useful discoveries, update the library with engine version, evidence and limitations; distinguish tested techniques from researched or proposed ones.

At the start of project work, read `Documentation/PROJECT-MEMORY.md` for John's long-term direction. Keep it current with dated, user-approved decisions as conversations continue. Distinguish ambitions and proposals from verified implementation, and record explicit changes to previous decisions.

Before visual work on this project, read `STYLING.md` and inspect `Reference images/Styling-Base-Standard.png`. They contain the user's approved art direction and are the persistent reference for asset selection, Blender modeling, Unreal materials, lighting, foliage, and environment dressing.

Read `Documentation/GAME-CANON.md` for setting and gameplay constraints. Preserve the approved architecture and functional requirements when interpreting concept images. Do not treat incidental generated details as changes to canon or geometry.

Keep `STYLING.md` current with user-approved styling decisions and verified implementation benchmarks. Do not mark concepts or unfinished work as completed Unreal results.
